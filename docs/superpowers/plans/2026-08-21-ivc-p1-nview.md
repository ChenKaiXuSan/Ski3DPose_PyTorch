# IVC P1 N-View Composition Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and run a provenance-controlled 1/2/3/4-view composition evaluation around the frozen MMSports CanonFuse3D checkpoint.

**Architecture:** A pure group builder creates 180 nested camera groups. A focused multi-view dataset intersects valid frame indices across all four cameras before loading a shared 30-frame window. The evaluator runs every unique pair through the existing two-view trainer forward path and aggregates pair predictions without changing model weights.

**Tech Stack:** Python 3.11, PyTorch, PyTorch Lightning, NumPy, Matplotlib, unittest.

**Spec:** `docs/superpowers/specs/2026-08-21-ivc-p1-nview-design.md`

## Global Constraints

- Use fold 0 and the checkpoint `logs/train_unity/crossview_fusion/2026-05-14/04-55-35/checkpoints/last.ckpt`.
- Propose exactly 180 four-camera base groups before missing-data filtering.
- Use one common frame intersection and one ground-truth tensor for every nested N condition in a base group.
- Write only under `logs/ivc_p1/nview/`.
- Do not modify the published model architecture or checkpoint.

```python
@dataclass(frozen=True)
class CameraGroup:
    group_id: str
    person_id: str
    action_id: str
    layer: int
    cameras: tuple[str, str, str, str]

def nested_cameras(group: CameraGroup, n_views: int) -> tuple[str, ...]:
    indices = {1: (0,), 2: (0, 2), 3: (0, 1, 2), 4: (0, 1, 2, 3)}
    if n_views not in indices:
        raise ValueError("n_views must be one of 1, 2, 3, 4")
    return tuple(group.cameras[i] for i in indices[n_views])
```
